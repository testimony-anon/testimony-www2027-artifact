# Confirmed defects of the subject applications

This catalog records nine confirmed application defects, D1–D9, in Conduit, RWA and Paperless-ngx. Confirmation uses controlled reproduction on the pinned, unmodified applications. D1–D7 retain their original reproduction records; D8 adds the existing Paperless pagination reproduction and its recorded adjudication; D9 adds the independent duplicate-like reproduction of 2026-10-20. These are defect investigations, not new generation experiments: no model or Testimony pipeline was used for the independent reproductions. Frozen M12 outcomes and initial review labels are preserved; subsequent adjudications are recorded separately.

The current [94-candidate classification](../eval/ui_semantics/refuted-review-20260923/final-classifications-94.json) contains **23 candidates linked to confirmed defects, 63 candidate errors, 8 ill-posed scenarios, and 0 unconfirmed leads**. Linked candidates are not distinct defects: D1 accounts for 5, D8 for 14, and D2, D5, D7 and D9 for one each. D3, D4 and D6 came from the earlier semantic review, source inspection, compositions or reproduction work.

D1–D7 correspond to the original lead IDs L1–L8 (L5 was not reproduced and has no defect ID). D8 is the Paperless pagination finding; D9 corresponds to lead L9.

## 3. Relation to the upstream repositories

- RWA (`cypress-io/cypress-realworld-app`): several pull requests from January 2026 (#1678, #1681, #1682, #1683, #1685, #1688) claim that the payment/request logic of `createTransaction` and `updateTransactionById` is inverted; none was merged as of 2026-09-12 (#1688 still open). The pinned commit `bdf6169` postdates these pull requests: its `createTransaction` already settles payments immediately, but `updateTransactionById` still transfers funds, marks the transaction complete and notifies on every update of a request transaction, whatever the new `requestStatus`. The description of #1688 says its fix only negates `if (isRequestTransaction(transaction))` in `updateTransactionById`, without distinguishing accept from reject and without an idempotency guard (its diff was not checked line by line). No upstream issue or pull request was found for notification ownership (D3), self-notification (D4) or the unauthenticated GraphQL resolver (D7).
- Conduit (`TonyMckes/conduit-realworld-example-app`): no upstream report was found for D5 or D6.
- Paperless-ngx (D8): the archived 2026-09-23 investigation documents issue #12437 and PR #12440. The pinned version contains the fix for default ordering, but explicit `ordering=-created` drops the ID tie-breaker. This catalog reuses that historical source check and its stored reproduction evidence.
- RWA (D9), checked 2026-10-20: [issue #111](https://github.com/cypress-io/cypress-realworld-app/issues/111) included prevention of repeated likes and was closed by merged [PR #112](https://github.com/cypress-io/cypress-realworld-app/pull/112). Its [like-specific fix](https://github.com/cypress-io/cypress-realworld-app/commit/843b637900fbb54ba25675ce112e4e45a47d67bd) disables the UI button after a user has liked the transaction. At the inspected default-branch commit [`develop@0729f68`](https://github.com/cypress-io/cypress-realworld-app/blob/0729f68ac220f7cda4ad09c5693dba11d7c532c6/backend/database.ts#L608-L643), the API still creates and appends a like without checking for an existing `(userId, transactionId)` pair. The four relevant route, storage and UI files are byte-identical to the pinned reproduction version. See the [upstream investigation](../eval/ui_semantics/bug-leads-20261020/rwa-duplicate-like/UPSTREAM-STATUS.md) for the historical fix, current source inspection and search record. The [September cutoff check](../eval/ui_semantics/bug-leads-20261020/rwa-duplicate-like/UPSTREAM-STATUS.md#september-2026-cutoff), conducted retrospectively on 2026-10-22, confirms the same UI/API status at commit `9dfcb986` (2026-09-29); the reproduction and original investigation remain dated 2026-10-20.
